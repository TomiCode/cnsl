# cnsl

A self-hosted server and dashboard for TRMNL e-ink devices: Go backend, Vue 3 dashboard, SQLite,
screens rendered with headless Chrome. Design docs live in a separate repository (`../docs`).

Status: **phase 3** — layouts & images: framework split layouts and free regions, transparent
regions over a background image or slideshow, image screens, an image library with dithering
options (Floyd–Steinberg, Atkinson, ordered). Earlier phases: screens in Monaco rendered by headless
Chrome, playlists, gray calibration, devices/approvals/telemetry/logs, virtual device.

## Connecting a TRMNL

1. Set `CNSL_DEVICE_PUBLIC_URL` to the device listener as your network sees it, e.g. `http://192.168.1.10:8081`.
2. In the TRMNL's Wi-Fi setup portal, enter that URL as the custom server.
3. The device appears under **Devices → Waiting for approval** with the pairing code it shows on its screen. Approve it.

No hardware? Open **Devices → Virtual device**: a browser device that speaks the same protocol.

## Layout

```
cmd/cnsl/              entry point
api/openapi.yaml       dashboard API contract (OpenAPI 3.0) — source of truth
internal/config/       CNSL_* environment config
internal/dashboard/    dashboard API implementation (+ SSE); gen/ is generated by oapi-codegen
internal/device/       device lifecycle: provisioning, approval, telemetry, logs, images
internal/events/       in-process pub/sub feeding the SSE stream
internal/firmware/     device listener (/api/setup, /api/display, /api/log, /images)
internal/imaging/      grayscale, resize, tone curve, quantize/dither, 1/2/4-bit PNG encoder
internal/render/       page composition, headless browser, render pipeline, scheduler, calibration
internal/tmpl/         screen template engine (html/template + helpers)
internal/assets/       vendored trmnl-framework release (scripts/vendor-framework.sh)
internal/migrations/   embedded SQL migrations (golang-migrate)
internal/store/        SQLite (modernc, sqlx)
web/                   Vue 3 + Vite + Tailwind dashboard, embedded into the binary
```

## Development

Requirements: Go 1.27+, Node 24+, yarn 1.x, and Chrome or Edge for rendering (found automatically;
or point `CNSL_CHROME_URL` at a headless-shell container).

`go test ./...` includes a real-browser render test; `go test -short ./...` skips it. Set
`CNSL_RENDER_OUT=<dir>` to dump its images.

To update the screen framework: `scripts/vendor-framework.sh ../trmnl-framework <version>` and bump
`assets.FrameworkVersion`.

```bash
cd web && yarn install && yarn build   # once, so the binary has a dashboard to embed
go run ./cmd/cnsl                      # dashboard on :8080, device API on :8081
```

For frontend work run Vite alongside the Go server (it proxies `/api` to `:8080`):

```bash
cd web && yarn dev                     # http://localhost:5173
```

### After changing `api/openapi.yaml`

```bash
go generate ./...                      # Go server stubs + models (internal/dashboard/gen)
cd web && yarn gen:api                 # TypeScript types (web/src/api/schema.d.ts)
```

Generated files are committed.

### Migrations

Add `internal/migrations/NNNN_name.up.sql` and `.down.sql`. They are embedded in the binary and
applied on startup.

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `CNSL_ADDR` | `:8080` | Dashboard listener |
| `CNSL_DEVICE_ADDR` | `:8081` | Device listener |
| `CNSL_DEVICE_PUBLIC_URL` | — | Device listener URL as devices see it, e.g. `http://192.168.1.10:8081` |
| `CNSL_DATA_DIR` | `./data` | SQLite database, rendered images, uploads, cache |
| `CNSL_CHROME_URL` | — | Remote headless Chrome; empty = launch a local one |
| `CNSL_RENDER_BASE_URL` | `http://localhost:<port>` | URL Chrome uses to reach the dashboard listener |
| `CNSL_TIMEZONE` | `TZ`, else the system zone | Household timezone |
| `CNSL_LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `CNSL_LOG_FORMAT` | `text` | `text` or `json` |

## Docker

Edit the IP addresses in `compose.yml`, then:

```bash
docker compose up -d --build
```
